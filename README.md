Rotating the screen destroys and recreates the Activity (onPause -> onStop -> onSaveInstanceState -> onDestroy, followed by onCreate -> onStart -> onResume), preserving and restoring the log state via onSaveInstanceState and savedInstanceState. In contrast, pressing the Home button moves the Activity to the background without destroying it (onPause -> onStop -> onSaveInstanceState), allowing the app to resume the existing instance through onStart -> onResume without triggering onCreate again. Adding recordEvent("onSaveInstanceState") and filtering Logcat with LabCheckLifecycle verified this exact lifecycle sequence across rotation, backgrounding, and manual check-in events. Initial setup challenges included locating app/build.gradle.kts in the Project tree to enable viewBinding = true and resolve ActivityMainBinding errors, as well as switching activity_main.xml from Design to Code view to paste the layout XML.
